# تسليم Codex وClaude —25أكتوبر2026

هذه قناة ملفات مشتركة داخل نسخة العمل الوحيدة، وليست اتصالًا مباشرًا أو مراقبًا يعمل في الخلفية. GitHub main مرجع التسليمات المنشورة؛ ملف مكتوب لا يعني أن الطرف الآخر قرأه.

## بداية كل جولة
1. اقرأ docs/STATUS.md، وافحص Git والمالك والعمليات قبل الكتابة؛ اسحب main إذا لم توجد تغييرات محلية تتعارض.
2. اقرأ الرسائل المفتوحة في docs/design/CONTRACT-REQUESTS.md وردودها في docs/handoff/claude.md؛ ثم هاندوف مالكك فقط للأعمال الأخرى.
3. عند الاستلام اكتب رقم الرسالة وحالة الاستلام في ملفك، مع قرار أو عائق وخطوة تالية. لا تضع علامة استلام نيابة عن الطرف الآخر.

## القنوات والملكية
- Codex يكتب رسائله وإيصالات استلامه وطلبات تعديل العقد في docs/design/CONTRACT-REQUESTS.md، وأدلته في docs/handoff/codex.md.
- Claude يكتب ردوده إلى أرقام تلك الرسائل في docs/handoff/claude.md أو ملف docs/dev/ يربطه من هاندوفه. لا يكتب Codex داخل ملف Claude، ولا يكتب Claude داخل صندوق Codex.
- عقد docs/SCENE-CONTRACT.md يملكه Claude؛ manifest والصور يملكها Codex. المناقشة لا تغيّر العقد تلقائيًا.
- STATUS ملخص فقط؛ كل طرف يعدل سطوره. هذه الآلية تكمل docs/OWNERSHIP.md ولا تنقل ملكية الكود أو Blender.

## شكل الرسالة
رقم ثابت، مرسل ومستقبل، تاريخ، commit المصدر، المطلوب، مسارات التسليم، دليل الفحص، الحالة، ورقم الرد إن وصل.

الحالات: «بانتظار الاستلام» ← «تم الاستلام» ← «مقبول/يحتاج تعديل/عائق» ← «مغلق بعد التحقق». الموافقة الجمالية للمستخدم منفصلة عن القبول التقني. طلب مكتوب أو push ناجح ليس دليل قراءة أو تنفيذ.

## التسليم
قبل تغيير الملكية: فحوص مرتبطة بالتغيير، هاندوف مختصر، commit/push للملفات المملوكة فقط، ثم مرجع commit في الرسالة التالية أو إيصال DELIVERY الخارجي. لا تنشر Blender أو الرندرات الخام. لا حلقة انتظار؛ إن كان الطرف الآخر غير نشط يُسجل الانتظار وتُستكمل الأعمال المستقلة المصرح بها.

المطبق الآن: Codex استلم العقد وسجل الرد أدناه؛ تبني Claude لهذه الآلية واستلامه الرد ينتظران تأكيده في ملفه.
