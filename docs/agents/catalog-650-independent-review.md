# Independent review: nullable catalog metadata and Foodista batch — 21 October 2026

Scope: read-only review of `lib/domain/recipe_catalog.dart` against HEAD, `test/catalog_unknown_metadata_test.dart`, the four rows in `data/recipes/catalog-650-20261021/foodista/chunk-001.json`, their adjacent review notes and cited source snapshots. No code or reviewed-data changes were made.

## Findings

1. **P2 — known `totalTime: NaN` passes validation.** In [recipe_catalog.dart](../../lib/domain/recipe_catalog.dart#L148), `total` is checked only for numeric type and whether the absolute difference exceeds epsilon. For `NaN`, `difference.abs() > 1e-6` is false, so a fully known recipe with finite prep/cook values and a NaN total is accepted. Reject non-finite totals explicitly and add a known-metadata NaN regression case in [catalog_unknown_metadata_test.dart](../../test/catalog_unknown_metadata_test.dart).

2. **P2 — public scaling constructor breaks source compatibility and bypasses validation.** `ScaledCatalogRecipe` was callable as `ScaledCatalogRecipe(recipe, servings)` at HEAD; it now requires a third positional `sourceServings` at [recipe_catalog.dart](../../lib/domain/recipe_catalog.dart#L213). Existing external Dart callers no longer compile. The public constructor also accepts zero/negative source or target servings directly, bypassing the checks in `CatalogRecipe.forServings`, and can expose an invalid factor. Preserve the two-argument known-yield form or make construction private/factory-validated. `CatalogStep.fromJson` keeps its old positional call through the optional named argument, but `minutes`, `CatalogRecipe.servings`, `prepMinutes`, and `cookMinutes` changing to nullable types are source-level API changes that callers must handle.

3. **P2 — Tabbouleh amount’s unit is inferred.** The raw source line is `1 Juice from lemon` in [chunk-001.review.json](../../data/recipes/catalog-650-20261021/foodista/chunk-001.review.json); the candidate converts this to amount `1`, unit `حبة`, name `ليمونة معصورة` in [chunk-001.json](../../data/recipes/catalog-650-20261021/foodista/chunk-001.json#L454). The amount is present in the source, but a whole lemon is not the stated unit. Keep the source phrase as an unscaled unknown amount/unit, or document an authoritative parsing decision.

4. **P3 — Mantou’s paired diameter loses the numeric inch value.** The source says `approximately 2.5cm/1 in.`; the candidate says `نحو2.5سم/بوصة` at [chunk-001.json](../../data/recipes/catalog-650-20261021/foodista/chunk-001.json#L618). It retains 2.5 cm but turns the second measure into a dangling unit. Translate it as `نحو 2.5 سم (1 بوصة)` to preserve both source values clearly.

5. **Test gap — the legacy fingerprint assertion is self-consistency only.** The “known legacy shape and fingerprint stay unchanged” test at [catalog_unknown_metadata_test.dart](../../test/catalog_unknown_metadata_test.dart#L104) compares the current implementation’s result with itself after round-trip; it does not pin HEAD’s serialized JSON or a pre-change fingerprint. Inspection found legacy `metadataPolicy` omitted when null and the old known `totalTime` preserved as the validated prep+cook sum, so no concrete legacy serialization regression was found. A fixed HEAD-derived fixture/hash would make the compatibility claim meaningful.

## Four Foodista translations

- Source ingredient lines in the review sidecar match the snapshots for Pad Thai, Korean fried chicken, Lebanese tabbouleh, and Chinese mantou. Numeric source quantities, alternatives, ranges, optional ingredients, and unknown amounts are represented accurately overall; source line provenance is adjacent in the review file. No guessed yield or recipe total time was found. Tabbouleh copies the source’s `Serves 2`; the 12 mantou pieces are correctly not promoted to 12 servings.
- The Arabic method summaries retain source action order and material numeric facts. The Korean row preserves the 350°F source temperature and explicitly avoids treating the breadcrumb test as a guarantee. The Mantou optional apple filling stays part of that source recipe rather than becoming a fifth recipe.
- Explicit source-stage durations remain in the Arabic step text but are not structured in `duration` (for example, Pad Thai’s soak/simmer and Tabbouleh’s one-hour refrigeration). This keeps the schedule incomplete rather than inventing a whole-recipe time. If the step duration field is intended to capture a single explicit step duration even when other steps are unknown, the direct single-action waits can be added; otherwise the current null schedule is internally consistent.
- All four candidates keep unknown metadata null with `source-unknowns-v1`; no fake zero/default was observed. `hasCompleteSchedule` gates `schedule` and known-yield scaling goes through validated `forServings`. The direct public `ScaledCatalogRecipe` constructor remains the validation bypass noted above.

No kitchen testing, runtime approval, or culinary validation is implied by this review.
