# سُفرة — نموذج Flutter تجريبي

نموذج عربي باتجاه RTL لتطبيق هاتف يبدأ بمكونات البيت. واجهة الويب هنا للمعاينة أثناء التطوير؛ المنتج المقصود هو Android وiOS.

## التشغيل

يتطلب Flutter 3.47.7 أو نسخة متوافقة، وDart 3.13.5. من مجلد المشروع:

```bash
flutter pub get
flutter run -d chrome
```

للفحص:

```bash
flutter analyze
flutter test test
flutter build web
```

في مساحة الجلسة الحالية، Flutter موجود محليًا في `../../work/flutter_sdk`؛ على Windows يمكن استعمال `..\..\work\flutter_sdk\bin\flutter.bat` بدل `flutter`.

### نسخة الحساب والحفظ

```bash
flutter run -d chrome --dart-define-from-file=config/firebase.web.json
flutter build apk --release --target-platform android-arm64 --dart-define-from-file=config/firebase.android.json
```

الإعدادات تخص مشروع `sofra-c03a1` فقط، وهي معرفات تطبيق عامة وليست مفاتيح إدارة. تشغيل التطبيق دون هذه الإعدادات يستخدم حفظًا محليًا على الجهاز. وجود الإعدادات يشغل تسجيل الدخول بالبريد وكلمة المرور وحفظ Firestore؛ يجب تفعيل موفر البريد ونشر `firestore.rules` قبل الاستخدام.

الحفظ السحابي يتطلب اتصالًا؛ لا يعرض نجاحًا عند فشل الكتابة. تعارض نسخة أحدث على جهاز آخر يمنع الكتابة فوقها. هذه المرحلة لا تتضمن دمج تعديلات عدة أجهزة أو مزامنة العمل دون اتصال.

حزمة ARM64 مخصصة لتجربة Android مثل Samsung S24 Ultra، وموقعة بمفتاح اختبار محفوظ في ذاكرة GitHub المؤقتة. قبل توزيع مستقر نجهز مفتاح إصدار محفوظًا بشكل دائم؛ إذا فُقد مفتاح الاختبار قد يلزم إعادة التثبيت.

## جرّب التدفق

1. ابدأ من الترحيب، وأدخل اسمك واسم البيت الاختياري، ثم عدد الأشخاص والوجبات المعتادة.
2. اختر المطابخ المفضلة والحساسية الاختيارية؛ الحساسية فيها بحث وإضافة اختيار مخصص، ويمكن تخطي الخطوتين.
3. ادخل التطبيق، وافتح تبويب «تلجتي». اضغط «جرّبي بمكونات جاهزة» أو أضف مكونات يدويًا، ثم جرّب فلاتر التلجة والفريزر والدولاب.
4. اختر وصفة. مثال الفراخ بالرز والسلطة لأربعة يظهر عجز الفراخ والطماطم.
5. شاهد تكلفة ما سيُستهلك، وتكلفة عبوات شراء الناقص بشكل منفصل.
6. أضف الوجبة إلى السفرة؛ المخزون لا ينقص عند التخطيط.
7. حاكِ شراء العبوات الناقصة، ثم انتقل بين خطوات الطبخ.
8. أكد الانتهاء لتُخصم المقادير من المخزون، وافتح «تلجتي» لرؤية الباقي.

## ما يعمل فعلاً في هذا النموذج

- ترحيب و5 خطوات إعداد، مع رجوع وتخطي للاختيارات غير الإلزامية.
- تنقل بين النهاردة وتلجتي والوصفات والسفرة وبيتي، وتعديل بيانات البيت وعدد الحصص من 1 إلى 12.
- إضافة مكونات من قائمة محددة، وتعديل كمياتها أو حذفها بكمية 0، وعرض مكانها.
- بحث الوصفات وحفظها وفلتر المحفوظة والسريعة ومن الموجود. تفضيل الأكلات السريعة يرتب الوصفات حسب وقتها.
- تسجيل تفضيلات المطابخ والوجبات والحساسية داخل الجلسة. تنبيه صريح لوصفة البيض أو الألبان عند تسجيل الحساسية المطابقة؛ التنبيهات ليست تحققًا طبيًا أو ضمانًا للسلامة.
- مقارنة الكمية المطلوبة بالموجودة، وإعادة الحساب عند تغيير الحصص.
- فلترة الوصفات، واحتساب تكلفة المكونات المستهلكة وتكلفة عبوات الشراء.
- إضافة عبوات الشراء تجريبيًا للمخزون، ثم خصم المقادير بعد تأكيد الطبخ.
- اختبارات وحدات للمحرك واختبار للتدفق بحجم هاتف، مع اختبار تكامل على محاكي iOS في GitHub Actions.

## ما يزال محاكاة أو خارج هذه المرحلة

- كل الوصفات والأسعار والمقادير أمثلة مصرية غير موثقة للاستخدام الفعلي؛ لا تعتمد عليها كبيانات أسعار أو تغذية حديثة.
- رسومات الشيف والطعام رسوم متجهية أصلية مرسومة داخل Flutter، وليست صور أطباق حقيقية.
- زر شراء الناقص يحاكي الإضافة فقط؛ لا يوجد متجر أو دفع.
- الحساب والحفظ أضيفا للنسخ المهيأة بـFirebase؛ النسخ دون إعدادات Firebase تحفظ محليًا. مشاركة البيت بين حسابات متعددة لم تُنفذ.
- الصوت والباركود والتعرف على الصور والفواتير والمؤقتات والتنبيهات غير منفذة.
- تخصيص الوصفات لكل المطابخ والتفضيلات الصحية والتحقق الشامل من مسببات الحساسية والبدائل لم تُنفذ. الوصفات الأربع المتاحة مصرية.

## اتجاه التصميم

تم تطبيق مبادئ ملف «دروس تصميم الواجهات»: مسار واضح قبل الرسم، اختيار رئيسي لكل شاشة، مسافات ثابتة، مكونات مشتركة، حالات فارغة ورجوع وتخطي وبحث. الشخصية الأصلية «طماطم الشيف» والأطباق مرسومة بأشكال مستديرة وظلال وطبقات خفيفة؛ الإلهام من مرح دولينجو ولغته الهندسية، دون استخدام شخصيته أو شعاره.

التخطيط مبني على `Row` و`Column` و`Wrap` و`Expanded` و`SafeArea` مع محتوى قابل للتمرير، وحد أقصى 480 للمعاينة. لا تُستخدم إحداثيات ثابتة لترتيب واجهة الشاشة. إحداثيات الرسم محصورة داخل اللوحات المتجهية للشخصية والطعام.

الأزرار تهبط عند الضغط وتعود لوضعها الطبيعي؛ الشخصية لها دخول قصير بلا حركة لا نهائية. إعداد تقليل الحركة يوقف انتقالات الواجهة، ويُحترم إعداد الجهاز أيضًا. الخط العربي Tajawal مضمّن محليًا مع رخصته، ولا يحتاج تحميلًا من الإنترنت.

## البنية

- `lib/data/demo_data.dart`: بيانات مصرية تجريبية موسومة.
- `lib/domain/models.dart`: كائنات المكونات والمخزون والوصفات.
- `lib/domain/recipe_engine.dart`: حساب الحصص والعجز والتكلفة وخصم المخزون، مستقل عن الواجهة.
- `lib/main.dart`: الواجهة وتدفق الشاشات.
- `lib/ui/design.dart`: ألوان ومكونات وزر الضغط والاختيارات والبطاقات المشتركة.
- `lib/ui/illustrations.dart`: شخصية سفرة وأطباق الطعام المتجهية الأصلية.
- `assets/fonts`: خط Tajawal المضمّن ورخصة OFL.
- `.github/workflows/flutter-checks.yml`: تحليل واختبارات وبناء ويب وAPK واختبار صلاحيات Firestore؛ محاكي iOS اختياري عند التشغيل اليدوي.
- `tool/run_ios_flow.py`: يحد وقت اتصال اختبار iOS، ويعيد المحاولة مرة فقط عند التعليق؛ فشل الاختبار الفعلي يظل فشلًا. تحفظ المهمة صور المحاكي للتشخيص.

لا يستخدم النموذج أي AI API مدفوع.
